SECTION 01

Model Specification模型规格

target Dependent Variable因变量

The target variable is churn_probability, a continuous value ranging from 0 to 1 that represents each customer's likelihood of leaving the platform. Because this is a continuous outcome rather than a binary label, we treat the prediction task as a regression problem using regularized linear models. This approach preserves the granularity of the original probability values, allowing the model to distinguish between customers at 15% churn risk and those at 85% churn risk — a distinction that would be lost in a simple binary classification framework.

input Independent Variables自变量

receipt_long
Transactional

Behavioral metrics derived from the transaction log that capture how frequently and how much each customer transacts on the platform.

tx_count avg_tx_value total_tx_volume monthly_transaction_count transaction_frequency weekend_transaction_ratio avg_daily_transactions
group
Demographic

Customer profile attributes that describe who the customer is, including personal characteristics and their relationship tenure with the platform.

age household_size income_bracket (dummy-encoded) customer_tenure
touch_app
Engagement

Indicators of how deeply each customer interacts with the platform's products, digital tools, and support channels.

active_products app_logins_frequency feature_usage_diversity credit_utilization_ratio satisfaction_score nps_score support_tickets_count resolved_tickets_ratio

In total, the model considers 19 independent variables spanning transactional behavior, demographics, and engagement metrics. The income_bracket variable (Low, Medium, High, Very High) is dummy-encoded into 3 indicator columns, bringing the actual feature matrix to 21 columns before regularization.

SECTION 02

Regularization Methods正则化方法

With 21 features in the model matrix, ordinary least squares (OLS) regression risks overfitting — fitting noise in the training data that does not generalize to new customers. Regularization addresses this by adding a penalty term to the loss function that discourages large coefficients. We use the glmnet package in R, which efficiently fits both Lasso and Ridge regression via coordinate descent and selects the optimal penalty strength through cv.glmnet() with 10-fold cross-validation.

filter_alt

Lasso (L1 Regularization)

Primary model for feature importance

Lasso adds the sum of absolute values of coefficients as a penalty term: λ × Σ|βj|. This creates a powerful effect — as λ increases, coefficients of less important variables are shrunk to exactly zero, effectively removing them from the model.

This property makes Lasso our primary model for feature selection. By examining which variables survive at different λ values, we can identify the minimal set of customer attributes that drive churn prediction. Analysts can use the λ slider in the Shiny app to visually observe how the model progressively simplifies.

  • •Automatic variable selection via coefficient zeroing
  • •Sparse, interpretable models at higher λ
  • •Ideal for answering: "Which features matter most?"
compress

Ridge (L2 Regularization)

Validation model for comparison

Ridge adds the sum of squared values of coefficients as a penalty: λ × Σβj². Unlike Lasso, Ridge never shrinks coefficients to exactly zero — instead, it pulls all coefficients proportionally toward zero, retaining every variable in the model.

We use Ridge as a validation model to cross-check the Lasso results. If the Ridge model achieves similar predictive accuracy while retaining all variables, it confirms that the features Lasso selected are indeed the most important ones. If Ridge significantly outperforms Lasso, it suggests that many small-contribution features collectively improve prediction.

  • •Retains all variables with proportional shrinkage
  • •Better when many features contribute modestly
  • •Serves as benchmark to validate Lasso feature selection
tune The λ Parameter: Controlling Model Complexity

The regularization parameter λ (lambda) is the single most important hyperparameter in both Lasso and Ridge regression. It controls the trade-off between fitting the training data closely and keeping the model simple:

λ = 0 (No regularization)

Equivalent to ordinary least squares. All features retained with full coefficients. Risk of overfitting.

λ = λ.min (Optimal)

Selected by 10-fold CV. Minimizes prediction error. Balances bias and variance for best generalization.

λ → ∞ (Maximum)

Lasso: all coefficients zero (null model). Ridge: all coefficients near zero. Maximum bias, minimum variance.

We use cv.glmnet() with 10-fold cross-validation to identify two key λ values: λ.min (the λ that minimizes mean cross-validated error) and λ.1se (the largest λ within one standard error of the minimum, yielding a more parsimonious model). Both models are pre-trained offline, saved as .rds files, and loaded at Shiny startup for instant predictions.

SECTION 03

Feature Engineering特征工程

Beyond the raw independent variables, we engineer three derived features that capture higher-order customer behavior patterns. These features are computed during data preparation and added to the model matrix alongside the original variables. Each encodes a specific business hypothesis about what drives churn.

category product_diversity_ratio

active_products / 5

(max possible products = 5)

Normalizes the number of active products to a 0–1 scale. A customer with only 1 of 5 products (ratio = 0.20) is less embedded in the platform ecosystem than one using all 5 (ratio = 1.0). Higher product diversity implies higher switching costs, which should reduce churn risk. This feature captures the "stickiness" dimension that raw product count alone does not convey at a normalized scale.

support_agent ticket_resolution_gap

support_tickets_count × (1 − resolved_tickets_ratio)

Measures the absolute number of unresolved support tickets. A customer with 10 tickets and 50% resolution has a gap of 5 unresolved tickets, while one with 2 tickets and 50% resolution has a gap of only 1. This interaction term captures the frustration dimension: it is not just about having tickets, but about having tickets that remain unsolved. Higher values signal service delivery failures that may push customers to churn.

sentiment_dissatisfied satisfaction_gap

base_satisfaction − satisfaction_score

Computes the difference between the customer's baseline (initial) satisfaction and their current satisfaction score. A positive gap indicates that the customer's satisfaction has declined over time, which is a stronger churn signal than low absolute satisfaction alone. A customer who dropped from 9 to 5 is more at risk than one who was always at 5 — the trajectory of dissatisfaction matters as much as the level.

SECTION 04

Variable Importance变量重要性

The variable importance plot is the central analytical output of Module 3. It displays the absolute values of Lasso regression coefficients at the user-selected λ value as a horizontal bar chart, providing a direct answer to the question: "Which customer attributes most strongly predict churn?"

bar_chart Coefficient Bar Chart系数条形图

The bar chart ranks features by the absolute magnitude of their Lasso coefficients. Each bar is color-coded to indicate the direction of effect:

Positive coefficients (increases churn)

Features like support_tickets_count or satisfaction_gap that, when increased, push predicted churn probability higher.

Negative coefficients (decreases churn)

Features like active_products or satisfaction_score that, when increased, reduce predicted churn probability.

linear_scale Interactive λ Slider

Users adjust the λ slider to observe how the model simplifies in real time. This interaction teaches the bias-variance tradeoff visually:

Low λ → Complex model

Most features have non-zero coefficients. The chart shows many bars of varying lengths. The model fits training data closely but may overfit.

Optimal λ (λ.min) → Best predictive model

The cross-validated optimum. A balanced set of features remain. This is the recommended setting for predictions.

High λ → Sparse model

Only the strongest predictors survive. The chart shows just a few bars. Simple and interpretable, but may sacrifice accuracy.

As the user drags the slider from low to high λ, they can watch variables "disappear" one by one — the last features standing are the ones the model considers most essential for predicting churn.

lightbulb Observation 7 — A small set of features dominates churn prediction

Using a pre-trained Lasso regression model with L1 regularization, the variable importance plot reveals that a relatively small subset of customer attributes accounts for the vast majority of predictive power. As λ increases beyond the optimal value, features like satisfaction_score, ticket_resolution_gap, credit_utilization_ratio, and product_diversity_ratio are the last to be shrunk to zero, indicating that engagement and service quality metrics are more predictive of churn than raw transactional volume or demographic attributes. This insight suggests that retention strategies should focus on the customer experience rather than simply encouraging more transactions.

SECTION 05

What-If Simulator假设模拟器

The What-If Simulator is the flagship interactive component of Module 3. It transforms the pre-trained glmnet model from a static analytical artifact into a live decision-support tool. Business users can build hypothetical customer profiles, see the predicted churn probability update in real time, and explore which interventions most effectively reduce churn risk — all without writing a single line of code.

sliders

Input Panel输入面板

Each customer attribute has its own dedicated slider or input control, organized into logical groups (Transactional, Demographic, Engagement). Users build a hypothetical customer profile by adjusting individual values:

  • •tx_count: 0–500 (step 10)
  • •avg_tx_value: 0–5,000,000 COP
  • •customer_tenure: 0–120 months
  • •active_products: 1–5
  • •credit_utilization_ratio: 0.0–1.0
  • •satisfaction_score: 1–10
  • •nps_score: 0–10
  • •support_tickets_count: 0–20
  • •resolved_tickets_ratio: 0.0–1.0

Engineered features (product_diversity_ratio, ticket_resolution_gap, satisfaction_gap) are computed automatically from the slider values.

speed

Prediction Output预测输出

The predicted churn probability is displayed as a large, real-time gauge visualization that updates instantly as the user adjusts any slider. The gauge uses color-coding to convey risk severity at a glance:

Low Risk 0% – 30%

Customer is likely to remain active. No immediate intervention needed.

Medium Risk 30% – 60%

Customer is wavering. Proactive engagement recommended.

High Risk 60% – 100%

Customer is highly likely to churn. Immediate retention action required.

The prediction is computed by calling predict() on the pre-trained glmnet model object loaded from the .rds file at startup. Response is near-instantaneous since no model fitting occurs at runtime.

lightbulb Observation 8 — Changing specific customer attributes meaningfully shifts predicted churn risk

The What-If Simulator demonstrates that churn probability is not a fixed fate — it responds meaningfully to changes in specific, actionable customer attributes. For example, increasing a customer's active_products from 1 to 3 may reduce predicted churn probability by 15–20 percentage points, while resolving outstanding support tickets (improving resolved_tickets_ratio from 0.4 to 0.9) can reduce churn risk by a similar magnitude. These simulations translate the statistical model into concrete, actionable business strategies: product cross-selling, support queue prioritization, and satisfaction recovery programs each have quantifiable expected impacts on retention.

SECTION 06

Model Performance模型性能

Before trusting the model's predictions, we validate its performance using standard regression diagnostics. These visualizations and metrics are displayed in the Shiny app to give users confidence in the prediction quality and transparency into the model's limitations.

monitoring

Cross-Validation Performance交叉验证性能

The CV performance plot displays λ vs. Mean Squared Error (MSE) across the 10-fold cross-validation. Two critical λ values are marked with vertical dashed lines:

  • •λ.min — The λ that achieves the lowest cross-validated MSE. This is the model with the best predictive accuracy.
  • •λ.1se — The largest λ within one standard error of the minimum. This yields a sparser, more parsimonious model with slightly higher error but better interpretability.

The curve typically shows a U-shape: error decreases as λ increases from zero (reducing overfitting), hits a minimum, then rises again (underfitting). The flat region between λ.min and λ.1se indicates that the model is robust to the exact λ choice within this range.

scatter_plot

Predicted vs. Actual (Calibration)预测值与实际值（校准）

The calibration scatter plot compares the model's predicted churn probabilities (x-axis) against the actual observed churn probabilities (y-axis) for each customer. A well-calibrated model produces points that cluster tightly around the 45-degree diagonal line.

  • •Points above the line indicate underestimation — the model predicts lower churn than actual.
  • •Points below the line indicate overestimation — the model predicts higher churn than actual.
  • •Systematic deviations at the extremes (very low or very high churn) reveal calibration issues that may require model refinement.
equalizer

Residual Distribution残差分布

A histogram of residuals (actual − predicted) assesses whether the model's errors are well-behaved. For a good regression model, residuals should be:

  • •Centered at zero — The model does not systematically over- or under-predict.
  • •Approximately normal — Most errors are small, with few large errors in either direction.
  • •Symmetric — Errors are equally distributed above and below zero, with no heavy tails.

Skewed or heavy-tailed residuals would suggest that the linear model assumption is violated and alternative approaches (e.g., quantile regression or non-linear models) should be considered.

analytics

Key Performance Metrics关键性能指标

Two summary metrics quantify overall model quality:

R² Coefficient of Determination

Proportion of variance in churn_probability explained by the model. An R² of 0.75 means the model captures 75% of the variation, leaving 25% unexplained. Higher is better, but values above 0.95 on real-world data may suggest data leakage.

RMSE Root Mean Squared Error

Average prediction error in the same units as churn_probability (0–1 scale). An RMSE of 0.08 means predictions are off by about 8 percentage points on average. Lower is better. Compared against the standard deviation of churn_probability as a baseline.
