SECTION 01

Data Sources数据来源

The COFINFAD dataset is composed of two relational tables linked by customer_id. Together they capture both the static profile of each customer and their full year of transactional behaviour. All data is synthetically generated to mirror a Colombian financial institution's retail banking portfolio.COFINFAD数据集由两个通过 customer_id 关联的关系表组成。它们共同捕获每位客户的静态档案及其全年交易行为。所有数据均为合成生成，以模拟哥伦比亚金融机构的零售银行业务组合。

Data Cleaning & Imputation数据清洗与缺失值填补

healing

Missing Value Treatment缺失值处理

The credit_utilization_ratio column contained the only meaningful missingness in the dataset:

Missing values 37.5%

18,263 of 48,723 records

Strategy: Median imputation grouped by income_bracket

Why not mean? The mean is sensitive to extreme values prevalent in financial data. Grouped median preserves the distributional shape within each income tier without being pulled by outliers.

search_insights

Outlier Detection异常值检测

Transaction amounts exhibit heavy right-skew with extreme high-value entries that can distort distance-based algorithms.

warning Extreme values detected in transaction amounts
Strategy Winsorization at 1st / 99th percentile
Applied to Clustering features only

Note: Raw values are retained for EDA so that box plots and histograms reflect the actual distribution. Winsorized values are used exclusively in the clustering pipeline where Euclidean distance would otherwise be dominated by outliers.

SECTION 04

Feature Engineering特征工程

Beyond the raw columns, we engineer derived features that capture latent behavioural signals not directly observable in the original data. These features are critical for both the clustering and prediction modules.除了原始列之外，我们还构建了衍生特征，捕获原始数据中不可直接观察到的潜在行为信号。这些特征对聚类和预测模块至关重要。

category

product_diversity_ratio

active_products / 5

Measures how broadly a customer uses the bank's product portfolio (savings, credit card, loan, insurance, investment). A ratio of 1.0 indicates full adoption; lower values flag single-product customers at higher churn risk.

support_agent

ticket_resolution_gap

support_tickets × (1 − resolved_ratio)

Quantifies unresolved service burden. A customer with many tickets and a low resolution rate has a high gap — a strong signal of dissatisfaction and potential churn.

sentiment_dissatisfied

satisfaction_gap

base_satisfaction − satisfaction_score

Captures the delta between a customer's baseline satisfaction (e.g., at onboarding) and their current score. A positive gap signals deteriorating sentiment over time.

show_chart

spending_volatility

sd(monthly) / mean(monthly)

The coefficient of variation of monthly transaction totals. High volatility indicates irregular spending patterns — potentially seasonal workers or customers with unstable financial behaviour.

weekend

weekend_transaction_ratio

weekend_tx / total_tx

Proportion of transactions occurring on Saturday or Sunday. This behavioural timing feature distinguishes personal-use customers (higher weekend activity) from business-oriented ones.

SECTION 05

Standardization for Clustering聚类标准化

Clustering algorithms that rely on distance metrics (K-Means, hierarchical) are highly sensitive to variable scale. Without standardization, features measured in large units (e.g., transaction amounts in COP) would dominate the distance calculation, drowning out features with smaller numeric ranges (e.g., ratios between 0 and 1).依赖距离度量的聚类算法（K-Means、层次聚类）对变量尺度高度敏感。如果不进行标准化，以大单位衡量的特征（如以COP为单位的交易金额）将主导距离计算，淹没数值范围较小的特征（如0到1之间的比率）。

functions

Z-Score NormalizationZ-Score 标准化

z = (x − μ) / σ

Each value is centred at zero with unit variance

Implemented via R's scale() function. This ensures every feature contributes equally to Euclidean and Manhattan distance calculations during cluster assignment.
